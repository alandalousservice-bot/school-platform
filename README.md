# منصة الإدارة المدرسية والمطعم

منصة كاملة (خادم + واجهة) جاهزة للتشغيل، مبنية فعليًا واختُبرت مسارات الـ API الرئيسية.

## المحتوى
```
school-platform/
├── backend/     خادم FastAPI + قاعدة بيانات (SQLite افتراضيًا، وPostgreSQL جاهز للإنتاج)
├── frontend/    واجهة React (صفحة رئيسية احترافية + تسجيل دخول + 3 واجهات حسب الدور) + دعم عمل دون اتصال (PWA)
├── scripts/     سكربت النسخ الاحتياطي اليومي لقاعدة البيانات
└── docker-compose.yml   نشر كل شيء بأمر واحد
```

---

## الطريقة الأسرع: Docker Compose (موصى بها للنشر الفعلي)

```bash
cp .env.example .env
# عدّل DB_PASSWORD و SECRET_KEY داخل .env بقيم حقيقية
docker compose up -d --build
```

هذا يشغّل قاعدة بيانات PostgreSQL + الخادم + الواجهة (عبر nginx على المنفذ 80)
دفعة واحدة، ويعيد التشغيل تلقائيًا عند انقطاع الكهرباء وعودتها. الواجهة تستدعي
`/api/...` بمسارات نسبية، ويمرّرها nginx داخليًا لحاوية الخادم — لا حاجة لمعرفة
IP الخادم مسبقًا عند البناء.

بعد أول تشغيل، عبّئ بيانات تجريبية مرة واحدة:
```bash
docker compose exec backend python seed.py
```

**النسخ الاحتياطي اليومي** (لا توجد سحابة، النسخ تُحفظ محليًا/على USB):
```bash
chmod +x scripts/backup.sh
# أضف السطر التالي إلى crontab -e على حاسوب المدرسة:
0 2 * * * /المسار-الكامل/school-platform/scripts/backup.sh >> /var/log/school-backup.log 2>&1
```

## التشغيل اليدوي (تطوير محلي بدون Docker)

### ويندوز وأندرويد على نفس الشبكة

يمكن تشغيل الخادم على حاسوب ويندوز وفتح الواجهة من هاتف أندرويد متصل بنفس شبكة
Wi-Fi. اعرف عنوان IPv4 للحاسوب عبر `ipconfig` (مثلاً `192.168.1.20`) ثم شغّل:

```powershell
# نافذة PowerShell الأولى
cd backend
venv\Scripts\activate
python seed.py
uvicorn app.main:app --host 0.0.0.0 --port 8000

# نافذة PowerShell الثانية
cd frontend
$env:VITE_API_BASE="http://192.168.1.20:8000"
npm run dev -- --host 0.0.0.0
```

بعد ذلك افتح من أندرويد: `http://192.168.1.20:5173`.
يجب السماح للمنفذين `5173` و`8000` في Windows Firewall، وأن يكون الهاتف
والحاسوب على نفس الشبكة. في وضع الإنتاج يُفضّل استخدام Docker Compose وفتح
`http://192.168.1.20`؛ عندها تمرّر الواجهة طلبات API تلقائيًا عبر nginx.

لتثبيت الواجهة على أندرويد، افتحها في Chrome ثم اختر **إضافة إلى الشاشة الرئيسية**.
التثبيت الكامل كتطبيق PWA يتطلب HTTPS عند استخدام عنوان IP؛ أما التشغيل من
المتصفح عبر HTTP فيعمل مباشرة داخل الشبكة المحلية.

### الخادم (Backend)
```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt
python seed.py                  # يعبّئ بيانات تجريبية (مستخدمين + قسم + تلاميذ)
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

حسابات تجريبية بعد `seed.py`:
| الدور | اسم المستخدم | كلمة المرور |
|---|---|---|
| مدير | admin | admin123 |
| أستاذ | teacher1 | teacher123 |
| مشرف مطعم | restaurant1 | resto123 |

للانتقال إلى PostgreSQL يدويًا (بدون Docker): أنشئ ملف `.env` بجانب `app/` يحتوي:
```
DATABASE_URL=postgresql://user:password@localhost:5432/school
SECRET_KEY=غيّر-هذا-المفتاح-في-الإنتاج
```

توثيق تفاعلي لكل المسارات متاح تلقائيًا على: `http://<IP-الخادم>:8000/docs`

**تفعيل تقارير PDF بعربية صحيحة:** ضع ملف خط `.ttf` عربي (Amiri أو Noto Naskh
Arabic) في `backend/app/static/fonts/arabic.ttf` — التفاصيل في
`backend/app/static/fonts/README.md`. بدونه يعمل التصدير لكن بخط لا يدعم
العربية.

### الواجهة (Frontend)
```bash
cd frontend
npm install
npm run dev      # للتجربة أثناء التطوير
# أو
npm run build    # لبناء نسخة الإنتاج داخل مجلد dist/
```

عدّل عنوان الخادم عند النشر اليدوي (خارج Docker) عبر متغير البيئة `VITE_API_BASE`
(مثال: `VITE_API_BASE=http://192.168.1.100:8000 npm run build`).

## تنظيم الإدارة والميزانية

تحتوي لوحة المدير الآن على وحدة مستقلة لـ **الميزانية والاعتمادات**: تقسيم الاعتماد حسب المحور، إضافة البنود، تسجيل النفقات مع منع تجاوز المتبقي، وعرض الحركات الأخيرة وسجل التدقيق. تفاصيل طريقة التشغيل والاقتراحات المرحلية موثقة في [`docs/management-roadmap.md`](docs/management-roadmap.md).

## ما الذي تم بناؤه فعليًا (ومُختبر)

**الخادم:**
- مصادقة كاملة: تسجيل دخول، access/refresh tokens قابلة للإبطال، bcrypt لتشفير كلمات المرور
- صلاحيات كل مسار محكومة بدور المستخدم (RBAC حقيقي عبر Dependencies)
- مسار الأستاذ: عرض القسم الحالي تلقائيًا حسب اليوم والفترة، وتسجيل الغيابات
- مسار المطعم: مسح الوجبة بالباركود مع منع التكرار والتنبيه عند غياب التلميذ، وحركات المخزون
- مسار الإدارة: إحصائيات لحظية، سجل تدقيق كامل (Audit Log) لكل عملية حساسة، إدارة المستخدمين
- **تصدير تقرير غياب PDF** لأي مدى زمني، بتشكيل عربي صحيح (reshaping + BiDi)
- قابلية التبديل الفورية بين SQLite (تجربة) و PostgreSQL (إنتاج) — بما فيها محرك الاتصال (psycopg2) في requirements.txt

**الواجهة:**
- تصميم عربي RTL كامل بخط Tajawal، ونظام ألوان موحّد بهوية واحدة ولون ثانوي لكل قسم
- 3 واجهات مبنية فعليًا وتُبنى (build) بدون أخطاء: الإدارة، الأستاذ، المطعم
- تجديد تلقائي للتوكن عند انتهاء صلاحيته دون مقاطعة عمل المستخدم
- حماية المسارات حسب الدور (توجيه تلقائي إذا حاول مستخدم دخول واجهة لا يملك صلاحيتها)
- **عمل دون اتصال في تطبيق الأستاذ**: شارة حالة الاتصال، تخزين آخر قائمة قسم
  محليًا لعرضها دون اتصال، وحفظ الغيابات في IndexedDB عند انقطاع الشبكة مع
  مزامنة تلقائية عند عودتها (Background Sync حيث يتوفر + حدث `online` كبديل شامل)
- قابلة للتثبيت كتطبيق (PWA) على أجهزة لوحية داخل القسم

**النشر:**
- Docker Compose بأمر واحد (قاعدة بيانات + خادم + واجهة عبر nginx)، إعادة تشغيل تلقائية عند انقطاع الكهرباء
- سكربت نسخ احتياطي يومي جاهز لـ crontab

## قيود معروفة / خطوات لاحقة اختيارية

- التقارير العربية تحتاج ملف خط `.ttf` يُضاف يدويًا (انظر أعلاه) — لم يُضمَّن
  خط داخل المستودع لتفادي مشاكل التراخيص وحجم الملف.
- عمل دون اتصال مُفعَّل لتطبيق الأستاذ فقط (حسب الأولوية المتفق عليها)؛ يمكن
  تطبيق نفس المنطق على واجهة المطعم لاحقًا إن لزم (طابور مسح محلي مؤقت).
- ميزات اختيارية من وثيقة المعمارية لم تُبنَ بعد: بوابة ولي الأمر
  (`/api/parent/...`)، ودعم اللغة الفرنسية كخيار تبديل.
